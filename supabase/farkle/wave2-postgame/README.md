## Recovery protocol

Recovery locks scheduled/processing Farkle postgame timer rows in worker order,
then takes the existing exclusive creation/continuation advisory lock. It disables
creation and this additive continuation owner, rejects any Farkle ante/in-progress/
game-over state, cancels only Farkle postgame timers and restores the captured
shared function and metadata. Failure rolls the whole operation back. Farkle
configuration, state, events, settlement and receipt tables are retained. Existing
receipts remain readable through exact authorized duplicate calls.

Continuation holds the shared advisory lock until commit and uses round → game →
ordered-player row locks. It does not cancel its timer while holding those rows:
the canonical worker holds timer locks first. Late workers read the receipt and
complete without changing gameplay or balances. Connected completion and fallback
therefore share a single durable continuation owner.
